How prepare_data.py works

This script changes text into numbers. A model can then train on these numbers.

1. The full process

The script does five steps. Each step makes the data more ready for training.

The main idea: A model cannot read text. It reads only numbers. This script is a translator from text to numbers.

2. The task: summarize a dialogue

The script prepares data for summarization. The model reads a conversation. Then it writes a short summary.

The model is google/flan-t5-small. T5 is an encoder-decoder model. It has two parts:

  • The encoder reads the input. It makes a numeric description of the meaning.
  • The decoder uses this description. It writes the output one token at a time.

The input goes into the encoder. The labels are what the decoder must learn to write.

This is why each example needs two sets of token IDs. The input_ids go to the encoder. The labels tell the decoder the correct answer.

3. Load and select the data

# lines 12–14
full_dataset = load_dataset("knkarthick/dialogsum")
train_data = full_dataset["train"].select(range(50))
test_data  = full_dataset["test"].select(range(10))

load_dataset downloads DialogSum from the Hugging Face Hub. It stores a copy on your disk. The next run uses this copy.

DialogSum has three splits. Each row has four columns: id, dialogue, summary, and topic.

Bar width shows the number of rows. The script uses a very small part.

Why so few rows? A small subset makes each run fast. You can find errors in seconds, not hours. Use more rows when the code works correctly.

.select(range(50)) keeps rows 0 to 49. It does not pick rows at random. For a random sample, use .shuffle(seed=42).select(range(50)).

4. Tokenization

The tokenizer must match the model. Each model learns its own list of tokens, called the vocabulary. AutoTokenizer.from_pretrained(MODEL_NAME) loads the correct tokenizer for Flan-T5.

Look at these points:

  • Words can split. "Summarize" becomes three tokens: ▁Sum, mar, ize. A rare word uses more tokens than a common word.
  • The ▁ mark shows a space. It tells the tokenizer that a new word starts here.
  • The tokenizer adds </s> at the end. This token (ID 1) tells the model "the text stops here".
  • Same token, same ID. The colon : is always ID 10.

The attention mask

The tokenizer also makes an attention_mask. It has one number for each token. A 1 means "use this token". A 0 means "ignore this token, it is only padding". At this step, all values are 1, because the script does not add padding. See Section 9.

5. The prompt prefix

# lines 19, 22
PREFIX = "Summarize the following dialogue:\n\n"
prompts = [PREFIX + d for d in examples["dialogue"]]

The script adds an instruction to the start of each dialogue. Why?

Flan-T5 is instruction-tuned. Google trained it on many tasks. Each task started with a text instruction, for example "Translate to German:" or "Summarize:". So the model already knows how to follow instructions.

When the prefix tells the model the task, fine-tuning starts from a better point. The model already knows what "summarize" means. It only learns the style of DialogSum summaries.

Rule: Use the same prefix at training time and at prediction time. If you change the prefix, the model can give worse results.
Note: The T5 tokenizer removes newlines. The \n\n in the prefix does not become a token. Look at the token list above: : goes directly to ▁#. This causes no problem, but the newlines have no effect.

6. Truncation and maximum length

# lines 23–27
model_inputs = tokenizer(prompts, max_length=128, truncation=True)

max_length=128 sets a limit. truncation=True tells the tokenizer to cut any text that is longer than this limit. The tokenizer removes the tokens at the end. It keeps the </s> token.

Why use a limit? Longer inputs use more memory and more time. The memory for attention increases with the square of the length.

Important: In the 50 training rows, 44 inputs are longer than 128 tokens. The median input length is 193 tokens. The longest is 459 tokens. The model often does not see the end of the dialogue. But the summary often talks about the end. The model must then guess facts that it cannot see. Think about a larger max_length, for example 512.

The summaries are shorter. The limit for labels is 64 tokens. Only 3 of 50 summaries are longer than 64. The median summary is about 35 tokens.

7. Make the labels

# lines 28–33
labels = tokenizer(text_target=examples["summary"], max_length=64, truncation=True)
model_inputs["labels"] = labels["input_ids"]

The script tokenizes the summary a second time, as a target. The text_target argument tells the tokenizer "this is the output text". For T5, the result is the same as normal tokenization. Some other models use different rules for targets, so this argument keeps the code correct for all models.

Then the script takes only the input_ids from the summary. It stores them in a new key called labels. The model looks for this key name during training.

Each row now has three number columns. Input and label have different lengths. This is normal.

How training uses the labels

During training, the model makes a guess for each label token. Then it compares the guess with the real token. The difference is the loss. Training changes the model to make the loss smaller.

8. Apply the function to all rows

# lines 36–40
tokenized_train = train_data.map(tokenize, batched=True, remove_columns=train_data.column_names)

.map() runs tokenize on every row. It returns a new dataset. It does not change the old dataset.

batched=True

Without this option, .map() sends one row at a time. With this option, it sends a group of rows (1,000 by default). The function gets lists, not single values. That is why tokenize uses a loop: [PREFIX + d for d in examples["dialogue"]].

The tokenizer is fast with lists. It processes the full list in Rust code. So batched mode is much faster on large datasets.

remove_columns

This option deletes the old text columns. After tokenization, the model does not need them. If they stay, set_format("torch") and the trainer can fail, because they cannot change text into tensors.

9. Change to PyTorch format

# lines 46–47
tokenized_train.set_format("torch")

By default, a dataset row gives Python lists. After set_format("torch"), a row gives PyTorch tensors. The data on disk does not change. Only the output type changes when you read a row.

No padding yet

The rows have different lengths. One input has 128 tokens. Another can have 90. But a batch tensor must be a rectangle. All rows in a batch must have the same length.

This script does not pad. That is a good choice. A data collator adds padding later, one batch at a time. It pads each batch only to the length of its longest row. This uses less memory than padding all rows to 128.

Next step: At training time, use DataCollatorForSeq2Seq(tokenizer, model=model). It pads the inputs with 0. It pads the labels with −100, so the padding does not change the loss.
